# 叙事视频制作

目标是作出适合当前作品的判断。一起设计内容、观看体验和视觉形式，依据当前作品的条件选择方案。技术检查、观看反馈和审美验收分别记录。

## 入口与资料选择

1. 先读用户当前要求、项目约定、brief、现有时轴与最近反馈。分清当前意图、撤销方案、项目事实和助手推断；最新用户决定优先于旧稿。
2. 新片／重构读 [工作流](references/workflow.md)，在规划时使用 [导演设计](references/directing.md) 选择组织方式、转场和时间依据，并用 [声音](references/sound.md) 决定声音职能及是否需要各声部，不能只在出问题后补读。
3. 新建视觉方向或风格不适配时，在选色与大规模制作前读 [视觉判断](references/visual-direction.md)。物体／比例／层级问题读 [连续性](references/continuity.md)，质检或交付读 [质检](references/quality.md)。局部修订只读对应部分，不重新选择已成立的整片方案。
4. 需要从症状找根因或选择技法时读 [判断方法](references/judgment.md)。项目自带词表可查相关节点，但例子、数值和附带的旧项目指令不自动成为本片要求。
5. 项目明确提供创作偏好时读 [偏好使用约定](references/creator-profile.md)，只采用当前创作者已确认的倾向；本 Skill 不自带任何人的默认偏好。旧作仅在用户明确指定沿用或对比时读，先写明沿用哪些维度。

## 从条件作决定

关键选择用一条短推理支撑：**当前要达到的效果 → 哪些条件影响选择 → 采用什么及原因 → 什么变化会让此选择不再适用 → 如何验证。** 不要求每个小决定填表。

同一推理用于叙事、视觉、转场、节奏、声音和质检。先分清：当前用户要求、事实与交付约束必须满足；艺术选择由内容目的、受众、观看条件与素材决定；技术检查只证明其覆盖范围。不能为了灵活而放松事实和证据，也不能用事实校验的严密度把创作选项变成通则。

叙事、媒介、配色、剪辑节奏和声部各自需要选择依据，再相互协调。逐项判断手绘怎样用色、技术内容怎样组织、切点是否平顺、音乐与动作怎样对应、是否需要旁白。参考历史作品时，说明经验适用于当前条件的原因。

当前明确要求优先。用户偏好可让一种方法优先进入候选，但不能代替适配判断。条件相同时允许延续已有方案，条件改变时应改变方案；不为证明“灵活”而刻意换风格，也不把题材名机械映射为一套色彩。

## 制作约束

- 按本片目的选择叙事结构。因果解释要看见动作与状态关系；观察、抒情、喜剧、比较可以采用其他结构。伏笔、高潮、故障和解法只在需要时采用。
- 技术片先确认实体、控制、数据、持久状态和失效边界。能力未知时区分事实、架构示意和假设；用户已授权示意就继续，不反复索取同一批准。
- 每拍明确观众如何理解或感受、注意落在哪里、为什么接下一拍。每个关键切点有交接或有意打断的理由；平顺、跳跃、静止与骤断均按本片需要选择。
- 使用回扣时要保留能被认出的线索。重复可以推进含义，也可以建立韵律、仪式、稳定感或持续观察；按本片用途评价，不能把重复一律删掉或强制加变化。
- 先试高风险镜头、动作与声音，再扩展。共享物体、语义、状态和事件时间，避免同物异形、接受即完成、计数倒退和音画各自计时。
- 物体按本片建立的世界规则摆放和运动。真实感作品遵守物理，风格化夸张需有一致动机。检查中间态、接触与遮挡，不用一张静帧代替运动判断。
- 局部改动先保存基线，限定范围，检查共享组件和相邻接缝；用户已接受的造型不随手重画。要回退时保留后来有效修改。
- 节奏先找本段的时间依据：理解、动作／表演、音乐、口述、期待或观察。声音先选职能与声部；允许无旁白、无音乐、静默或声音主导。实际有时间关系的层共用基准，按本片目标判断同步、错位、密度与读法。
- 持续推进已授权制作，在各阶段自行检查进展与质量，沿用用户已经给出的授权。关键意图未知时只问影响结果的问题，同时推进不依赖答案的部分。

## 工具与证据

实现使用 Remotion 时读取可用的 `remotion-best-practices` 及其相关路由，不复制一套可能过期的 API 指南。已有矢量／代码资产优先原生修改；需要位图时再选图像工具。不假设另一台机器有本项目模型、字体或媒体能力。

可用 [工作模板](assets/project-template/) 与 `scripts/video_workflow.py init PROJECT` 无覆盖地建立 `production/`。只启用当前项目需要的字段；已有项目可沿用自己的记录。不能为填满栏目新增旁白、伏笔、高潮或声效。

需要可追溯采样计划时，编辑 `production/review-spec.json`，从 Skill 目录运行（或用脚本绝对路径）：

```bash
python3 scripts/video_workflow.py plan /path/to/project/production/review-spec.json
python3 scripts/video_workflow.py verify /path/to/project/production/review-plan.json
```

工具只校验结构、列出采样帧并冻结明确列出的输入指纹；不执行渲染、播放、听辨或审美验收。`sources` 必须包含实际源码及媒体／字幕／字体／配置等输入，缺项不能声称冻结了全片。改动后先识别影响范围，重新生成受影响证据。

完成审查需分开记录：脚本推理、源帧、动态播放、听感、自动测量、最终编码、用户认可。报告具体版本、范围、证据和未完成项；不能把待播放写成已看完、把测量通过写成自然好听、把预览写成已交付 MP4。

## 交付与维护

交付实际产物、可运行入口、必要依赖和质检结论。优先修不符合当前意图、误导事实、破坏目标观看体验或交付的缺陷；不要把有意歧义、跳切、风格化或声音主导当成错误。根据请求导出，未经请求不自行发布。

沉淀“在什么条件下，为什么作出什么判断，以及什么反例会改变选择”。通用判断进入参考，偏好进入 profile，实际色板／素材／剧情／参数留在各自项目。未验证的修法标为候选，不以“有效经验”发布。复盘档案不随通用 Skill 自动加载。
